# Technology-agnostic engine; technologies live in the catalogue

The simulation engine knows only generic **Primitives** (a traffic source, a station that is a pool of workers with a bounded queue, routing to the next hop, a shortcut that completes work early such as a cache hit, scripted failures, metrics). Each component type in the catalogue is described as a combination of primitives plus its numbers (workers, service time, sizes, costs, C4 label). A **Technology Pack** (the web core, async, a possible GitLab CI pack) adds catalogue entries and levels; it changes the engine only when it needs a primitive that does not exist yet (for example fork/join for CI pipelines, work classes with their own durations, tag-based routing, autoscaling). We chose this from the first ticket because retrofitting it onto an engine that hard-codes servers and databases would mean rewriting the engine and its tests.
